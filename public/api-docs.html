SysRepWeb — API de Integração

API REST para integração com sistemas ERP externos. Expõe pedidos, clientes, produtos e formas de pagamento gerados pelo sistema de força de vendas.

REST JSON Bearer Token

Visão Geral

Todos os endpoints retornam dados em formato JSON com codificação UTF-8. As requisições devem ser feitas via HTTPS.

Base URL
https://api.nresolutions.com.br/api/v1

Paginação

Endpoints de listagem suportam paginação via parâmetros page e limit. O padrão é 100 registros por página.

ParâmetroPadrãoMáximo
page1—
limit100500

A resposta inclui o objeto meta com informações de paginação:

Exemplo de meta paginação
"meta": {
  "total": 348,
  "page": 1,
  "limit": 100,
  "pages": 4
}

Autenticação

A autenticação é feita via API Key, enviada no header de todas as requisições.

Header obrigatório:
Authorization: Bearer SUA_API_KEY
⚠️ Nunca exponha sua API Key em código front-end ou repositórios públicos. Em caso de comprometimento, solicite a revogação imediata.
Exemplo de requisição 
curl -X GET "https://api.nresolutions.com.br/api/v1/pedidos" \
  -H "Authorization: Bearer SUA_API_KEY" \
  -H "Content-Type: application/json"

Para obter sua API Key, entre em contato com o suporte da NC Sistemas.

Pedidos

GET /pedidos Lista todos os pedidos com filtros ▼

Retorna a lista de pedidos realizados pelos vendedores. Suporta filtros por período, status, vendedor e cliente.

Parâmetros de Query
ParâmetroTipoObrig.Descrição
data_inicio string Opcional Data inicial no formato YYYY-MM-DD. Ex: 2026-06-01
data_fim string Opcional Data final no formato YYYY-MM-DD. Ex: 2026-06-30
status string Opcional Filtra por status. Valores: PENDENTE, CONFIRMADO, CANCELADO, FATURADO
id_vendedor integer Opcional ID do vendedor para filtrar pedidos de um vendedor específico
id_cliente integer Opcional ID do cliente para filtrar pedidos de um cliente específico
page integer Opcional Página atual (padrão: 1)
limit integer Opcional Registros por página (padrão: 100, máximo: 500)

GET /pedidos/:id Detalhe de um pedido ▼

Retorna todos os dados de um pedido específico, incluindo itens completos.

Parâmetros de Path
ParâmetroTipoObrig.Descrição
id integer Sim ID do pedido no sistema
Exemplo de requisição
GET /api/v1/pedidos/1042

Utilitários

GET /ping Verifica se a API está online (sem autenticação) ▼

Endpoint público para verificar se a API está disponível. Não requer API Key.

Exemplo de resposta — 200 OK

Códigos de Resposta

A API utiliza os códigos HTTP padrão para indicar sucesso ou falha nas requisições.

CódigoStatusDescrição
200 OK Requisição bem-sucedida
400 Bad Request Parâmetros inválidos ou ausentes
401 Unauthorized API Key ausente, inválida ou revogada
404 Not Found Recurso não encontrado
500 Internal Server Error Erro interno — contate o suporte
Exemplo de resposta de erro
{
  "error": {
    "code": 401,
    "message": "API Key inválida ou não autorizada"
  }
}
